# Proposal: 云ERP教程中心（三端）

## Problem

云ERP（6 大核心能力、8 大业务模块、订单 7 环节全流程）缺少一个产品化的教程中心，用户上手成本高、教程内容分散且无法检索、运营无法量化内容效果，移动场景下完全无法学习。

### Evidence

- 帮助中心（jlc-erp.com/help）现状为静态文档站：无搜索、无收藏/历史、无"是否有帮助"反馈通道、无浏览数据统计
- 功能清单（产品管理知识库 V0.1 大纲）已明确列出三端缺口：前台（浏览/检索/互动/场景联动）、后台（内容管理/目录管理/审核/统计）、小程序（浏览学习/场景联动）全部为"待开发需求"
- 云ERP用户为电子制造企业多角色成员（销售/采购/生产/仓库/管理/财务），静态文档无法按角色推荐，新员工培训依赖口口相传

### Urgency

云ERP功能持续增多（立创生态打通后链路更长），学习成本随功能数线性上升；无数据反馈通道导致"没帮助"的教程无法被识别和优化。再不建设教程中心，用户激活与留存将持续受损。

## Proposed Solution

建设**云ERP教程中心子系统**，三端一体：

- **PC 前台**：教程首页（推荐/最新/热门）+ 分类浏览（映射 8 大模块）+ 检索（分类/标签/关键词）+ 详情阅读（步骤进度条、目录锚点、字号调节、阅读进度续读、上下篇）+ 互动（收藏/历史/有帮助评价/分享二维码）
- **管理后台**：教程 CRUD（轻量富文本图文+视频嵌入）+ 四态状态流转（草稿→待审核→已发布→已下架，驳回留原因）+ 多级分类树管理（排序/启停用/模块映射）+ 统计看板（浏览/互动/反馈分析/覆盖度）
- **小程序端（H5 形态）**：分类列表+搜索、详情阅读（与 PC 数据打通的收藏/历史/进度）、学习打卡积分、扫码直达

内容生产闭环：运营编辑 → 提交审核 → 管理员审核（通过=发布 / 驳回=留原因回草稿）→ 用户消费互动 → 数据回流统计看板 → 运营优化（编辑回审）。

### Innovation Highlights

- **教程分类 ↔ ERP 模块映射**：分类挂接云ERP模块，支撑"按角色推荐"（采购角色优先采购/库存教程）与后续系统内嵌引导——行业帮助中心少有把内容与产品功能模块做强映射的设计
- **三端一库**：PC/小程序同一账号体系，收藏、历史、阅读进度云端同步，PC 二维码扫码直达小程序同篇教程
- 标准做法的诚实说明：内容审核四态流转、富文本编辑、统计看板均为行业成熟方案的标准采纳，无创新必要

> 领域术语见 `.cache/glossary.md`（跨阶段共享术语表，拷问中即时维护）。

## Requirements Analysis

### Key Scenarios

**Happy path**
- 新用户首次进入教程中心 → 首页按其 ERP 角色推荐教程 → 分类/关键词找到目标教程 → 步骤式学习（进度续读）→ 收藏/评价
- 采购员在 PC 学"MRP 算料"，下班路上小程序继续学（进度同步）
- 运营新建"库位初始化"教程 → 提审 → 管理员通过 → 前台即时可见 → 浏览/反馈数据上看板
- 管理员看覆盖度统计发现"系统设置"模块 0 篇教程 → 安排运营补内容

**Edge / boundary**
- 空搜索结果、无已发布教程的停用分类、教程被下架后的收藏夹入口（提示已下架）
- 未登录用户点收藏/评价 → 引导选角色登录
- 已发布教程编辑保存 → 自动回"待审核"，前台仍展示旧版本直至新版本过审（本期简化：前台展示最新过审版本）

**Error scenarios**
- 审核驳回未填原因 → 阻断提交并提示；运营看到驳回原因后修改重提
- 删除已有教程的分类 → 阻断，需先移走教程
- 下架教程再重新发布 → 内容未变不需重审，一键回"已发布"

### Non-Functional Requirements

- 关键词搜索结果 1s 内返回（本地数据集 <100 篇）
- 详情页图片懒加载，弱网可读（教程用户常在车间弱网环境）
- 小程序端 375px 视口适配，字号可调（最大 20px 档位）
- 管理后台仅 admin/运营两级角色可登录，前台互动需登录（浏览免登录）

### Constraints & Dependencies

- 教程分类体系必须对齐云ERP 8 大模块 + 4 个通用分类（新手入门/最佳实践/常见问题/开放平台）
- 视频采用外链 URL 嵌入（mp4 直链播放），本期不做视频上传托管
- 留言反馈不公开展示（仅后台分析），规避 UGC 审核依赖
- demo 独立实现（含模拟 ERP 工作台页演示内嵌入口），不修改真实云ERP代码

## Alternatives & Industry Benchmarking

### Industry Solutions

- 帮助中心类：Intercom / Zendesk Guide / 飞书帮助中心（分类+检索+评价+后台内容管理，SaaS 标准形态）
- 产品内教育类：Stripe Docs（开发者文档标杆）、Notion 模板中心（模板+分类推荐）
- 国内 ERP 帮助中心：金蝶云之家/用友 YonHelp（多为静态文档+客服工单，缺互动与数据闭环）

### Comparison Table

| Approach | Source | Pros | Cons | Verdict |
|----------|--------|------|------|---------|
| Do nothing（维持静态帮助中心） | — | 零成本 | 检索/互动/数据/移动端四缺失，学习成本持续上升 | Rejected: 缺口已被功能清单正式立项 |
| 采购 SaaS 帮助中心（Intercom 类） | Intercom/Zendesk | 成熟快 | 内网不可达、无法与 ERP 模块/角色体系映射、费用 | Rejected: 模块映射与角色推荐是核心诉求 |
| 静态文档站升级（加搜索） | docsify 等 | 轻 | 仍无互动/审核/统计，运营闭环缺失 | Rejected: 只解决四分之一问题 |
| **自研三端教程中心** | 本方案 | 模块映射/角色推荐/三端同步/数据闭环全部可控 | 需自建内容管理/审核/统计 | **Selected: 核心诉求全部命中，且为公司内网可控** |

## Feasibility Assessment

### Technical Feasibility

用户侧约束：PC 现代浏览器（Chrome/Edge）、小程序 H5 形态（作业明确允许 web 形态替代原生）；无原生 App/插件依赖，纯 web 可达。

### Resource & Timeline

单人 + AI 编码工具（zcode），PRD/UI/开发/测试全流程一周内可完成 demo 级交付。

### Dependency Readiness

素材就绪（两份云ERP帮助中心 PDF 提供教程内容源）；无外部 API 依赖（视频外链除外，可降级为纯图文）。

## Assumptions Challenged

| Assumption | Challenge Tool | Finding |
|------------|---------------|---------|
| "教程必须支持视频上传托管" | Occam's Razor | Refined：视频外链 URL 嵌入即可满足演示与绝大多数 ERP 操作录屏场景（录屏托管在既有视频平台），上传托管进迭代池 |
| "留言应公开展示形成社区" | Assumption Flip（若公开：UGC 违规风险→需二次审核→闭环变长） | Overturned：留言仅进后台反馈分析，"有帮助/没帮助"量化已足够识别劣质教程 |
| "已发布教程可直接编辑生效" | Stress Test（错误内容即时上线风险） | Overturned：编辑保存回"待审核"，保证线上内容始终过审 |
| "场景联动 6 项本期全做" | Need Gate（新手引导弹窗/消息推送去掉后核心学习闭环是否断裂？） | Refined：不断裂→进迭代池；保留 4 项核心联动 |
| "小程序必须原生开发" | XY Detection（真实需求是移动场景可学，不是原生包体） | Refined：H5 形态满足，原生壳进迭代池 |

## Scope

### Core Path（核心路径 — 本轮交付）

- 前台：教程首页（推荐/最新/热门/8 模块入口）、列表页（分类/标签/关键词）、详情页（步骤进度条、目录锚点、字号调节、阅读进度、上下篇、收藏、有帮助评价+留言、分享链接+二维码、按角色关联推荐）
- 前台互动基础：收藏、浏览历史（含已下架提示）、选角色登录
- 场景联动 ×4：按角色推荐（首页+详情关联推荐）、扫码直达（PC 二维码→小程序同篇）、ERP 页内嵌教程入口（模拟工作台页右下角"查看教程"）、小程序学习打卡积分
- 后台：两级角色登录、教程 CRUD+复制+轻量富文本（标题/加粗/列表/图片/视频外链）、四态状态流转+审核队列（驳回必填原因）、AI 生成审核预留 Tab（mock）、分类树管理（多级/排序/启停用/删除保护）、教程置顶排序、模块映射维护、统计看板（浏览/收藏/反馈率/没帮助优先清单/模块覆盖度空白区）
- 小程序端：首页（角色推荐+分类宫格+打卡入口）、列表+搜索、详情（字号调节/进度续读/收藏）、收藏与历史（与 PC 打通）、学习打卡+积分+徽章
- 数据与账号：种子分类 12 个、种子教程 16~20 篇（取材云ERP业务知识）、多角色演示账号

### Iteration Pool（迭代池 — 后续轮次处理）

- 新手引导弹窗（首次进模块弹推荐教程）——推迟原因：非闭环必需，且与扫码直达/内嵌入口功能重叠
- 消息推送关联（审批待办推送操作教程）——推迟原因：依赖真实消息通道，demo 仅有 mock 意义
- 视频上传托管——推迟原因：需对象存储与转码服务
- 原生小程序壳——推迟原因：H5 已覆盖移动学习诉求
- 阅读完成率深度分析（步骤粒度漏斗）——推迟原因：需步骤级埋点改造

### Out of Scope

- 真实云ERP系统代码改动（导航入口仅做模拟页演示）
- 公司通用登录（passport）对接——demo 用本地账号
- 多租户数据隔离的落地实现（PRD 中说明设计思路即可）
- 教程评论公开社区、教程付费、作者激励体系

## Key Risks

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| 种子教程内容深度不足，演示说服力弱 | M | M | 全部取材两份官方 PDF 的真实业务知识（6 能力/7 环节/痛点解法表），保证业务正确性 |
| 三端交互范围过大导致交付延期 | M | H | 4+2 分流已锁定核心路径；开发按端串行（后台→前台→小程序），每端可独立验收 |
| 轻量富文本编辑器能力不足（复杂排版丢失） | L | M | 教程内容以步骤式图文为主，排版需求简单；明确编辑器能力边界写入 PRD |
| 阅读进度多端同步出现不一致 | M | L | 进度以百分比单值存储，后写覆盖，冲突以最新为准（学习场景可接受） |

## Success Criteria

- [ ] 8 大 ERP 模块分类入口 100% 可达，每个模块分类下至少 1 篇已发布教程
- [ ] 关键词搜索（标题/摘要/标签）1s 内返回结果，空结果有明确引导
- [ ] 教程四态流转全链路线上可操作：新建→提审→驳回（含原因）→修改重提→通过发布→下架→重新发布
- [ ] PC 收藏的教程在小程序收藏列表同步可见（反向亦然）
- [ ] PC 详情页二维码扫码后小程序打开同一教程（同 URL 语义）
- [ ] 统计看板能展示每篇教程浏览量/收藏量/有帮助率，并按模块给出覆盖度与空白区
- [ ] 三端 Playwright 验收用例 100% 通过且报告含截图
