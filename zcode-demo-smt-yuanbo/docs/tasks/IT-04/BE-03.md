# BE-03 - 教程评价与分享打点（POST /api/feedbacks/:tutorialId 评价 upsert + 计数联动事务；share 端点联调验证，交付方 IT-02/BE-02）

<!-- REQUIRED:任务目标 -->
## 任务目标

> 来源：[tech-design.md#11-service-函数清单冻结命名评审修复补充](../../design/tech-design.md#11-service-函数清单冻结命名评审修复补充) / [tech-design.md#4-后端架构与处理流程](../../design/tech-design.md#4-后端架构与处理流程)

实现用户互动的两个写接口：

1. `upsertFeedback`（`server/src/routes/feedbacks.ts`，POST /api/feedbacks/:tutorialId）：每篇教程每人仅一条反馈记录（feedbacks 联合主键），可在有帮助/没帮助之间**修改切换**（AC-RULE-15 评价唯一可改）；helpful 变更时事务内联动 `tutorials.helpful_yes / helpful_no`（旧值 -1、新值 +1），helpful 不变仅改留言时计数不动；留言选填 ≤200 字、仅后台反馈分析可见（AC-RULE-20）。helpful_yes/helpful_no 是 AC-RULE-10 有帮助率/没帮助占比的分母分子来源。
2. share 联调验证（端点由 IT-02/BE-02 交付，本任务不重复实现）：每次分享动作 `share_count +1`（不去重、含游客、公开接口），仅对前台可见教程计数；本期仅数据留存不上看板，复制教程时清零的口径由 IT-02/BE-05 的 copyTutorial 保证。

PC 与小程序共用同一条评价记录（AC-FN-25），本任务即该记录的唯一写入方。

## 核心流程

> 每个步骤必须与 tech-design.md 中的业务逻辑一致，必须包含以下全部描述项，缺一不可。
> 每个步骤必须标注来源（tech-design.md 章节），不允许无来源的内容。

**1. 鉴权与参数校验（POST /api/feedbacks/:tutorialId）**
- 来源：[tech-design.md#6-异常处理与校验](../../design/tech-design.md#6-异常处理与校验)
- 输入：`Authorization: Bearer {token}` + 路径参数 `tutorialId` + 请求体 `{helpful: 1|0, comment?: string}`
- 处理逻辑：auth 中间件注入 user_id → 校验 helpful 枚举 → 校验 comment 长度
- 校验规则：
  | 字段 | 规则 | 失败返回 |
  |------|------|---------|
  | token | 必填有效 | HTTP 401 `{code:401, message:"未登录或登录已失效"}`（游客评价由前端弹登录引导，AC-EG-07） |
  | helpful | 必填、整数、∈ {0, 1} | HTTP 400 `{code:400, message:"helpful 必须为 0 或 1"}` |
  | comment | 选填、≤ 200 字 | HTTP 400 `{code:400, message:"留言不超过 200 字"}`（AC-RULE-20） |
- 输出：`{userId, tutorialId, helpful, comment}` 进入步骤 2

**2. 教程可见性校验**
- 来源：[tech-design.md#4-后端架构与处理流程](../../design/tech-design.md#4-后端架构与处理流程)（可见性 SQL 化）
- 输入：步骤 1 产物
- 处理逻辑：按 VISIBLE_SQL 校验教程前台可见
- 数据库操作：
  | 操作 | SQL 骨架 | 说明 |
  |------|---------|------|
- 输出：可见 → 进入步骤 3
- 异常处理：HTTP 404 `{code:404, message:"该教程不存在或暂不可见"}`

**3. 评价 upsert + 计数联动（单事务）**
- 来源：[tech-design.md#11-service-函数清单冻结命名评审修复补充](../../design/tech-design.md#11-service-函数清单冻结命名评审修复补充)（upsertFeedback 事务内联动计数）
- 输入：`{userId, tutorialId, helpful, comment}`
- 处理逻辑：查旧记录 → 三分支处理，反馈行与 tutorials 计数在同一事务内提交
- 数据库操作（单事务，按分支执行）：
  | 分支 | 操作 | SQL 骨架 | 说明 |
  |------|------|---------|------|
  | 无旧记录 | INSERT | `INSERT INTO feedbacks(user_id, tutorial_id, helpful, comment, updated_at) VALUES(?, ?, ?, ?, datetime('now','localtime'))` | 首次评价 |
  | 无旧记录 | UPDATE | `UPDATE tutorials SET helpful_yes = helpful_yes + 1 WHERE id = ?`（helpful=1）或 `... helpful_no = helpful_no + 1 ...`（helpful=0） | 新评价对应计数 +1 |
  | 有旧记录且 helpful 变更 | UPDATE | `UPDATE feedbacks SET helpful = ?, comment = ?, updated_at = datetime('now','localtime') WHERE user_id = ? AND tutorial_id = ?` | AC-RULE-15 修改切换 |
  | 有旧记录且 helpful 变更 | UPDATE ×2 | `UPDATE tutorials SET helpful_yes = helpful_yes - 1 WHERE id = ?` + `UPDATE tutorials SET helpful_no = helpful_no + 1 WHERE id = ?`（1→0 方向；0→1 反向对称执行） | 旧值 -1、新值 +1（AC-FN-05 计数联动） |
  | 有旧记录且 helpful 不变 | UPDATE | `UPDATE feedbacks SET comment = ?, updated_at = datetime('now','localtime') WHERE user_id = ? AND tutorial_id = ?` | 仅改留言，计数不动 |
- 事务边界：feedbacks 写入 + tutorials 计数更新包在同一事务，任一失败全部回滚（计数永不漂移）
- 输出：事务提交后的 `{tutorialId, helpful}`
- 异常处理：事务异常 → 500 回滚

**4. 组装评价响应**
- 来源：[../../design/api/post-api-feedbacks-tutorialId.md](../../design/api/post-api-feedbacks-tutorialId.md)
- 输入：步骤 3 产物
- 处理逻辑：读回 `helpful_yes / helpful_no` 与响应字段拼接
- 数据库操作：
  | 操作 | SQL 骨架 | 说明 |
  |------|---------|------|
- 输出：`{tutorialId, helpful, helpfulYes, helpfulNo}`（helpfulYes+helpfulNo 即 AC-RULE-10 分母）

**5. share 联调断言：调用 IT-02/BE-02 交付的 POST /api/tutorials/:id/share 两次 → GET /api/tutorials/:id 响应 shareCount +2（不重复实现端点）
- 输出：`{shareCount}`（HTTP 200 code=0）
- 异常处理：不可见/不存在 → HTTP 404 `{code:40404, message:"该教程不存在或暂不可见"}`
