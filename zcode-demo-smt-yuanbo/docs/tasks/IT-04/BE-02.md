# BE-02 - 浏览历史与阅读进度（POST /api/histories/:tutorialId 进度 upsert、GET /api/histories）

<!-- REQUIRED:任务目标 -->
## 任务目标

> 来源：[tech-design.md#11-service-函数清单冻结命名评审修复补充](../../design/tech-design.md#11-service-函数清单冻结命名评审修复补充) / [tech-design.md#4-后端架构与处理流程](../../design/tech-design.md#4-后端架构与处理流程)

在 `server/src/routes/histories.ts` 实现 histories 实体的 2 个接口，service 函数按 tech-design §11 冻结命名实现：

1. `upsertProgress`（POST /api/histories/:tutorialId）：同一用户同一教程仅一条历史记录（联合主键），progress 0–100 整数**单值覆盖更新**，跨端取最新值（AC-RULE-11，进度跨端同值的后端保障）；仅可对前台可见教程保存进度。
2. `listHistories`（GET /api/histories）：按最近阅读时间倒序，每条返回 progress 百分比与 isOffline 下架标注（AC-FN-23 / AC-EG-10 数据来源）。
3. progress=100 视为完成，是百科达人徽章（AC-RULE-12）与完成率（AC-RULE-13）的口径来源，本期仅数据留存。
4. 接口幂等可支撑前端"保存失败静默重试一次、回退最近成功保存值"的约定（AC-EG-17）。

## 核心流程

> 每个步骤必须与 tech-design.md 中的业务逻辑一致，必须包含以下全部描述项，缺一不可。
> 每个步骤必须标注来源（tech-design.md 章节），不允许无来源的内容。

**1. 鉴权校验（两接口共用前置）**
- 来源：[tech-design.md#6-异常处理与校验](../../design/tech-design.md#6-异常处理与校验)
- 输入：请求头 `Authorization: Bearer {token}`
- 处理逻辑：auth 中间件查 auth_tokens，命中注入 user_id
- 数据库操作：
  | 操作 | SQL 骨架 | 说明 |
  |------|---------|------|
  | SELECT | `SELECT user_id FROM auth_tokens WHERE token = ?` | token 有效性校验 |
- 输出：上下文中的 `userId`
- 异常处理：未命中 → HTTP 401 `{code:401, message:"未登录或登录已失效"}`

**2. 进度保存 upsert（POST /api/histories/:tutorialId）**
- 来源：[tech-design.md#4-后端架构与处理流程](../../design/tech-design.md#4-后端架构与处理流程)（核心链路 3：进度单值覆盖）
- 输入：路径参数 `tutorialId` + 请求体 `{progress: 60}`
- 处理逻辑：校验 progress 为 0–100 整数 → 按 VISIBLE_SQL 校验教程可见 → 单条 SQL 完成 upsert（INSERT 冲突时覆盖 progress 并刷新 updated_at）→ 读回保存值
- 校验规则：
  | 字段 | 规则 | 失败返回 |
  |------|------|---------|
  | progress | 必填、整数、0 ≤ progress ≤ 100 | HTTP 400 `{code:400, message:"progress 必须为 0-100 的整数"}` |
  | tutorialId | 必填、正整数，且满足前台可见口径 | HTTP 404 `{code:404, message:"该教程不存在或暂不可见"}` |
- 数据库操作：
  | 操作 | SQL 骨架 | 说明 |
  |------|---------|------|
  | SELECT | `SELECT id FROM tutorials WHERE id = ? AND {VISIBLE_SQL}` | 可见性校验（AC-RULE-02 口径） |
  | INSERT | `INSERT INTO histories(user_id, tutorial_id, progress, updated_at) VALUES(?, ?, ?, datetime('now','localtime')) ON CONFLICT(user_id, tutorial_id) DO UPDATE SET progress = excluded.progress, updated_at = datetime('now','localtime')` | upsert：单值覆盖、不追加历史行（AC-RULE-11） |
- 事务边界：单语句原子，无需额外事务
- 输出：`{tutorialId, progress, updatedAt}`（updatedAt = 刷新后的最近阅读时间）
- 异常处理：见校验规则表；重复提交同一进度幂等（updated_at 刷新、progress 不变），支撑 AC-EG-17 前端静默重试

**3. 浏览历史查询（GET /api/histories?page=&pageSize=）**
- 来源：[tech-design.md#3-api-接口总览](../../design/tech-design.md#3-api-接口总览)（用户行为分组）
- 输入：查询参数 `page`（默认 1）、`pageSize`（默认 20）
- 处理逻辑：校验分页 → 联表查询本人历史（标题/摘要读 published_* 快照列）→ 派生 isOffline → 组装分页
- 校验规则：
  | 字段 | 规则 | 失败返回 |
  |------|------|---------|
  | page | 整数 ≥ 1 | HTTP 400 `{code:400, message:"查询参数不合法"}` |
  | pageSize | 整数 1–100 | 同上 |
- 数据库操作：
  | 操作 | SQL 骨架 | 说明 |
  |------|---------|------|
  | SELECT | `SELECT h.tutorial_id, t.title, t.published_summary AS summary, t.tags, t.category_id, c.name AS categoryName, h.progress, (NOT (t.published_content IS NOT NULL AND (t.status='published' OR (t.status IN ('pending','draft') AND t.last_offline_at IS NULL)))) AS isOffline, h.updated_at FROM histories h JOIN tutorials t ON t.id = h.tutorial_id LEFT JOIN categories c ON c.id = t.category_id WHERE h.user_id = ? ORDER BY h.updated_at DESC, h.tutorial_id DESC LIMIT ? OFFSET ?` | 最近阅读时间倒序 + 进度百分比 + 下架标注（AC-FN-23 / AC-RULE-04） |
  | SELECT | `SELECT COUNT(*) AS total FROM histories WHERE user_id = ?` | 分页总数 |
- 输出：`{list:[{tutorialId,title,summary,tags,categoryId,categoryName,progress,isOffline,updatedAt}], total, page, pageSize}`
- 异常处理：401 同步骤 1；空列表返回 `list:[], total:0`（非异常）

**4. 统一响应组装**
- 来源：[tech-design.md#3-api-接口总览](../../design/tech-design.md#3-api-接口总览)
- 输入：各步骤产物
- 处理逻辑：包装 `{code:0, message:"ok", data}`；错误走统一错误中间件
- 输出：见两份 API 文档成功响应示例
