# BE-01 - 收藏管理（POST /api/favorites/:tutorialId、DELETE /api/favorites/:tutorialId、GET /api/favorites）

<!-- REQUIRED:任务目标 -->
## 任务目标

> 来源：[tech-design.md#11-service-函数清单冻结命名评审修复补充](../../design/tech-design.md#11-service-函数清单冻结命名评审修复补充) / [tech-design.md#4-后端架构与处理流程](../../design/tech-design.md#4-后端架构与处理流程)

在 `server/src/routes/favorites.ts` 实现 favorites 实体的全部 3 个接口（新增收藏 / 取消收藏 / 收藏列表），service 函数 `toggleFavorite`（增删合一）与 `listFavorites` 按 tech-design §11 冻结命名实现：

1. 新增收藏：仅可收藏前台可见教程（VISIBLE_SQL 口径），favorites 联合主键 (user_id, tutorial_id) 幂等，事务内联动 `tutorials.fav_count +1`（AC-RULE-09 当前有效收藏数口径）。
2. 取消收藏：不限制教程可见性（已下架教程的收藏也可取消），事务内联动 `fav_count -1`，幂等不重复扣减。
3. 收藏列表：按收藏时间倒序，已下架条目保留并返回 `isOffline=true` 供前端灰显标注"已下架"（AC-FN-20 / AC-EG-10 / UI-ELEM-02 的数据来源）。
4. PC 与小程序同库同数据源（AC-FN-15 跨端同步的后端基础），本任务不涉及任何端间同步机制。

## 核心流程

> 每个步骤必须与 tech-design.md 中的业务逻辑一致，必须包含以下全部描述项，缺一不可。
> 每个步骤必须标注来源（tech-design.md 章节），不允许无来源的内容。

**1. 鉴权校验（三个接口共用前置）**
- 来源：[tech-design.md#6-异常处理与校验](../../design/tech-design.md#6-异常处理与校验)
- 输入：请求头 `Authorization: Bearer {token}`
- 处理逻辑：auth 中间件以 prepared statement 查 auth_tokens → 命中则将 user_id 注入请求上下文，继续后续步骤
- 数据库操作：
  | 操作 | SQL 骨架 | 说明 |
  |------|---------|------|
  | SELECT | `SELECT user_id FROM auth_tokens WHERE token = ?` | token 有效性校验 |
- 输出：上下文中的 `userId`
- 异常处理：未命中 → HTTP 401 `{code:401, message:"未登录或登录已失效"}`（前端弹选角色登录，登录后回原页面原位置继续收藏，AC-FN-03）

**2. 新增收藏（POST /api/favorites/:tutorialId）**
- 来源：[tech-design.md#4-后端架构与处理流程](../../design/tech-design.md#4-后端架构与处理流程)（核心链路 3：跨端收藏/进度）
- 输入：路径参数 `tutorialId`（Integer）
- 处理逻辑：按 VISIBLE_SQL 校验教程前台可见 → 开启事务执行 `INSERT OR IGNORE` → 按影响行数决定是否联动计数 → 读回 fav_count
- 校验规则：
  | 字段 | 规则 | 失败返回 |
  |------|------|---------|
  | tutorialId | 必填、正整数，且教程满足前台可见口径（VISIBLE_SQL） | HTTP 404 `{code:404, message:"该教程不存在或暂不可见"}`（已下架/纯草稿/首次待审核均不可收藏） |
- 数据库操作（单事务）：
  | 操作 | SQL 骨架 | 说明 |
  |------|---------|------|
  | SELECT | `SELECT id FROM tutorials WHERE id = ? AND {VISIBLE_SQL}` | 可见性校验（AC-FN-20：不可见教程不可新增收藏） |
  | INSERT | `INSERT OR IGNORE INTO favorites(user_id, tutorial_id) VALUES(?, ?)` | 联合主键幂等（重复收藏不报错、不重复计数） |
  | UPDATE | `UPDATE tutorials SET fav_count = fav_count + 1 WHERE id = ?`（仅 INSERT 影响行数 = 1 时执行） | fav_count 联动 +1（AC-RULE-09 当前有效收藏数） |
  | SELECT | `SELECT fav_count FROM tutorials WHERE id = ?` | 读回归一化计数 |
- 事务边界：INSERT + UPDATE 包在同一事务，失败一并回滚（计数与关系永不分家）
- 输出：`{tutorialId, favorited: true, favCount}`
- 异常处理：见校验规则表；事务异常 → 500 回滚

**3. 取消收藏（DELETE /api/favorites/:tutorialId）**
- 来源：[tech-design.md#11-service-函数清单冻结命名评审修复补充](../../design/tech-design.md#11-service-函数清单冻结命名评审修复补充)（toggleFavorite 删除分支）
- 输入：路径参数 `tutorialId`
- 处理逻辑：校验教程记录存在（**不校验可见性**——已下架教程的收藏也可取消，isOffline 条目从列表移除）→ 事务内删除关系行并按影响行数联动计数
- 校验规则：
  | 字段 | 规则 | 失败返回 |
  |------|------|---------|
  | tutorialId | 必填、教程记录存在（任意状态） | HTTP 404 `{code:404, message:"教程不存在"}` |
- 数据库操作（单事务）：
  | 操作 | SQL 骨架 | 说明 |
  |------|---------|------|
  | SELECT | `SELECT id FROM tutorials WHERE id = ?` | 存在性校验（不限状态） |
  | DELETE | `DELETE FROM favorites WHERE user_id = ? AND tutorial_id = ?` | 幂等：未收藏时影响行数 0 |
  | UPDATE | `UPDATE tutorials SET fav_count = fav_count - 1 WHERE id = ? AND fav_count > 0`（仅 DELETE 影响行数 = 1 时执行） | fav_count 联动 -1，兜底不落负 |
- 输出：`{tutorialId, favorited: false, favCount}`
- 异常处理：401/404 同上；幂等重复取消返回成功且计数不变

**4. 收藏列表查询（GET /api/favorites?page=&pageSize=）**
- 来源：[tech-design.md#3-api-接口总览](../../design/tech-design.md#3-api-接口总览)（用户行为分组）
- 输入：查询参数 `page`（默认 1）、`pageSize`（默认 20）
- 处理逻辑：校验分页参数 → 联表查询本人收藏（标题/摘要读 published_* 快照列，保持前台口径）→ 逐行派生 isOffline → 组装分页元数据
- 校验规则：
  | 字段 | 规则 | 失败返回 |
  |------|------|---------|
  | page | 整数 ≥ 1 | HTTP 400 `{code:400, message:"查询参数不合法"}` |
  | pageSize | 整数 1–100 | 同上 |
- 数据库操作：
  | 操作 | SQL 骨架 | 说明 |
  |------|---------|------|
  | SELECT | `SELECT f.tutorial_id, t.title, t.published_summary AS summary, t.tags, t.category_id, c.name AS categoryName, t.view_count, t.fav_count, t.published_at, t.updated_at, f.created_at AS favoritedAt, (NOT (t.published_content IS NOT NULL AND (t.status='published' OR (t.status IN ('pending','draft') AND t.last_offline_at IS NULL)))) AS isOffline FROM favorites f JOIN tutorials t ON t.id = f.tutorial_id LEFT JOIN categories c ON c.id = t.category_id WHERE f.user_id = ? ORDER BY f.created_at DESC, f.tutorial_id DESC LIMIT ? OFFSET ?` | 收藏时间倒序 + isOffline 派生（AC-RULE-04 已下架条目保留并标注） |
  | SELECT | `SELECT COUNT(*) AS total FROM favorites WHERE user_id = ?` | 分页总数 |
- 输出：`{list:[{tutorialId,title,summary,tags,categoryId,categoryName,isOffline,viewCount,favCount,publishedAt,updatedAt,favoritedAt}], total, page, pageSize}`（tags 为 JSON 数组文本，出参反序列化为数组）
- 异常处理：401 同步骤 1；空列表返回 `list:[], total:0`（非异常）

**5. 统一响应组装**
- 来源：[tech-design.md#3-api-接口总览](../../design/tech-design.md#3-api-接口总览)
- 输入：各步骤产物
- 处理逻辑：按全局约定包装 `{code:0, message:"ok", data}`；错误经统一错误中间件输出对应 code/message
- 输出：见各接口 API 文档成功响应示例
