# BE-02 - 系统重置接口 POST /api/system/reset（admin 专属·清空重建种子）

<!-- REQUIRED:任务目标 -->
## 任务目标

> 来源：[tech-design.md#8-非功能实现](../../design/tech-design.md#8-非功能实现) / 接口契约 [post-api-system-reset.md](../../design/api/post-api-system-reset.md)

实现 `server/src/routes/misc.ts`（system 分组，对齐 tech-design §2 routes 目录）中的 `POST /api/system/reset`：

1. 鉴权：`authRequired` + `requireRole('admin')`（401 未登录 / 403 非 admin）。
2. 核心动作：调用 INFRA-03 交付的 `resetDatabase()`（事务内清空 9 表 + 重跑种子，auth_tokens 随之清空——所有登录态作废，与登出同机制）。
3. 响应：`{"code":0,"message":"重置成功","data":{categories:12,tutorials:24,users:8,messages:3,checkins:5}}`。
4. 异常：重置过程数据库异常 → 事务回滚数据保持原状 → 500 `"重置失败，请重试"`。

**AC 关联**：AC-OP-01（种子初始化的 HTTP 侧入口：重复执行第二遍数量不增加）、AC-NF-06（重置脚本可重复初始化、单文件交付）。

**边界说明**：AC-OP-01 第 3 点中"前台首页三区块显示 ≥1 条 / 统计看板 4 指标卡"依赖后续迭代页面，本任务只验证数据层计数与接口行为，页面断言由对应前端迭代回补。

<!-- REQUIRED:核心流程 -->
## 核心流程

**1. 鉴权**
- 来源：[post-api-system-reset.md](../../design/api/post-api-system-reset.md)
- 输入：Header Authorization
- 处理逻辑：`authRequired`（无/失效 token → 401 `"未登录或登录已失效"`）→ `requireRole('admin')`（operator/user → 403 `"无权限执行该操作"`）
- 输出：`req.user.role==='admin'` 放行

**2. 清空重建种子**
- 来源：[post-api-system-reset.md](../../design/api/post-api-system-reset.md) / [tech-design.md#8-非功能实现](../../design/tech-design.md#8-非功能实现)
- 输入：无（Body 空对象或不发送）
- 处理逻辑：调用 `resetDatabase()`（INFRA-03：事务内 DELETE 9 表 → 重跑种子 → 返回计数）；事务边界由 db.ts 保证
- 数据库操作：

  | 操作 | SQL 骨架 | 说明 |
  |------|---------|------|
  | DELETE | `DELETE FROM users/auth_tokens/categories/tutorials/favorites/histories/feedbacks/messages/checkins` | 清空（auth_tokens 清空=全部登录态作废） |
  | INSERT | 重跑种子（同 INFRA-03 步骤 2） | 重建 12/24/8/3/5 |

- 输出：`{categories:12, tutorials:24, users:8, messages:3, checkins:5}`
- 异常处理：事务失败自动回滚（数据保持原状）→ 捕获后 500 `"重置失败，请重试"`

**3. 组装响应**
- 来源：[post-api-system-reset.md](../../design/api/post-api-system-reset.md)
- 处理逻辑：计数包进 `ok(data)`，message 固定 `"重置成功"`
- 输出：`{"code":0,"message":"重置成功","data":{...5 项计数}}`

## 验收标准

每条标准必须是 Agent 可通过命令自动判定通过/失败的。按阶段组织，前一阶段全部通过后才可进入下一阶段。

### 阶段 1：开发验收

- [ ] `getDiagnostics` 0 Error；`cd server && npm run build` 退出码 0
- [ ] 正常重置：admin login 取 token → `curl -s -X POST http://localhost:3000/api/system/reset -H 'Content-Type: application/json' -H "Authorization: Bearer {adminToken}" -d '{}'` → `code:0` 且 `data` 五项计数 = `12/24/8/3/5`
- [ ] 重复执行第二遍：再次调用同一 curl → 计数仍为 `12/24/8/3/5`，不增加（AC-OP-01 第 2 点）
- [ ] 权限异常：operator login → 同接口 → 403 `"无权限执行该操作"`

### 阶段 2：自测验收

- [ ] API 正向验证：重置后 `cd server && npm run seed:check` 计数恢复 12/24/8/3/5 且四态 18/3/2/1（数据层复核）
- [ ] API 异常场景：未携带 token → 401 `"未登录或登录已失效"`
- [ ] 登录态作废验证：reset 前先登录取得 token → reset 后用旧 token 调 GET /api/auth/me → 401；重新 login 后可用（demo 行为，与登出同机制）
- [ ] 幂等复验：reset 连续 3 次计数恒定；重启服务后计数不变
- [ ] 自测报告含 3 次 reset 响应对比与旧 token 401 断言
