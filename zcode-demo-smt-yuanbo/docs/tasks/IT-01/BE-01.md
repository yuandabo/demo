# BE-01 - 认证接口 4 端点 + DB token 鉴权中间件（login / role-login / logout / me）

<!-- REQUIRED:任务目标 -->
## 任务目标

> 来源：[tech-design.md#4-后端架构与处理流程](../../design/tech-design.md#4-后端架构与处理流程) / 接口契约见下方 4 份 API 文档

实现认证域全部代码（对齐 tech-design §2：`src/auth.ts` + `src/routes/auth.ts`）：

1. **`src/auth.ts` 鉴权模块**：
   - `issueToken(userId)`：随机 16 hex token，INSERT `auth_tokens`
   - `authRequired` 中间件：解析 `Authorization: Bearer {token}` → 查库 JOIN users → 挂 `req.user`；无/失效 token → 401 `"未登录或登录已失效"`
   - `requireRole(...roles)` 工厂：`req.user.role` 不在列表 → 403 `"无权限执行该操作"`
2. **`src/routes/auth.ts` 4 端点**（行为逐条对齐 API 文档）：POST /api/auth/login（后台账号密码）、POST /api/auth/role-login（选角色快速登录）、POST /api/auth/logout（作废 token）、GET /api/auth/me（恢复登录态）。
3. 在 index.ts 挂载：4 个认证端点为公开路由；`authRequired` 作为后续业务路由的鉴权挂载点（AC-NF-04 后台接口鉴权全覆盖的机制就绪）。

**AC 关联**：AC-RULE-26（前台/小程序选角色快速登录 6 演示账号 + 后台 admin/operator 账号密码，错误统一"账号或密码错误"）、AC-NF-04（鉴权中间件与 token 机制）。

<!-- REQUIRED:核心流程 -->
## 核心流程

**1. POST /api/auth/login（后台账号密码登录）**
- 来源：[post-api-auth-login.md](../../design/api/post-api-auth-login.md)
- 输入：Body `{username, password}`
- 处理逻辑：非空校验 → `SELECT * FROM users WHERE username=?`（prepared）→ 无记录或 password 不匹配 → 统一 401 → `role='user'` → 403 `"请使用选角色登录"` → issueToken → 返回 `{token, user:{id,username,role,erpRole,displayName}}`
- 校验规则：

  | 字段 | 规则 | 失败返回 |
  |------|------|---------|
  | username | required，1-50，非空白 | 400 `"请输入账号和密码"` |
  | password | required，1-50 | 400 `"请输入账号和密码"` |
  | 账号/密码匹配 | 存在且密码相等（防枚举：不区分"不存在/密码错"） | 401 `"账号或密码错误"` |
  | 角色 | role ∈ {admin, operator} | 403 `"请使用选角色登录"` |

- 输出：`{"code":0,"message":"ok","data":{"token":"...","user":{...}}}`

**2. POST /api/auth/role-login（选角色快速登录）**
- 来源：[post-api-auth-role-login.md](../../design/api/post-api-auth-role-login.md)
- 输入：Body `{erpRole}`
- 处理逻辑：枚举校验（sales/purchase/produce/warehouse/manage/finance）→ 查同名演示账号 → issueToken → 返回（role 固定 user，erpRole 回显）
- 校验规则：

  | 字段 | 规则 | 失败返回 |
  |------|------|---------|
  | erpRole | required，六枚举之一 | 400 `"erpRole 参数不合法"` |
  | 演示账号存在 | users 表有该 username 且 role='user' | 401 `"账号或密码错误"`（种子未初始化场景） |

- 输出：同 login 结构（user.role='user'，user.erpRole=请求值）

**3. POST /api/auth/logout（登出作废）**
- 来源：[post-api-auth-logout.md](../../design/api/post-api-auth-logout.md)
- 输入：Header Authorization（经 authRequired）
- 处理逻辑：`DELETE FROM auth_tokens WHERE token=?` → 返回 `{"code":0,"message":"已退出登录","data":null}`
- 数据库操作：

  | 操作 | SQL 骨架 | 说明 |
  |------|---------|------|
  | DELETE | `DELETE FROM auth_tokens WHERE token = ?` | 登出即作废，后续该 token 401 |

- 异常处理：未带 token / token 不存在 → 401 `"未登录或登录已失效"`

**4. GET /api/auth/me（登录态恢复）**
- 来源：[get-api-auth-me.md](../../design/api/get-api-auth-me.md)
- 输入：Header Authorization（经 authRequired）
- 处理逻辑：authRequired 已查库 JOIN users 挂 req.user → 直接组装 `{id,username,role,erpRole,displayName,createdAt}`
- 数据库操作：

  | 操作 | SQL 骨架 | 说明 |
  |------|---------|------|
  | SELECT | `SELECT u.* FROM auth_tokens t JOIN users u ON u.id=t.user_id WHERE t.token=?` | 服务端查库校验（authRequired 共用） |

- 输出：`{"code":0,"message":"ok","data":{...用户五字段+createdAt}}`
- 异常处理：token 失效/被登出作废 → 401 `"未登录或登录已失效"`

**5. 鉴权中间件与挂载**
- 来源：[tech-design.md#4-后端架构与处理流程](../../design/tech-design.md#4-后端架构与处理流程)
- 处理逻辑：`authRequired` + `requireRole` 导出供全部后续业务路由复用（AC-NF-04）；公开路由仅限 4 个认证端点（后续迭代的公开读接口按其 API 文档登记白名单）
- 输出：中间件机制就绪，BE-02 直接 `requireRole('admin')`

## 验收标准

每条标准必须是 Agent 可通过命令自动判定通过/失败的。按阶段组织，前一阶段全部通过后才可进入下一阶段。

### 阶段 1：开发验收

- [ ] `getDiagnostics` 0 Error；`cd server && npm run build` 退出码 0
- [ ] 正常登录（admin）：`curl -s -X POST http://localhost:3000/api/auth/login -H 'Content-Type: application/json' -d '{"username":"admin","password":"123456"}'` → `code:0` 且 `data.token` 非空、`data.user.role="admin"`
- [ ] 选角色登录：`curl -s -X POST http://localhost:3000/api/auth/role-login -H 'Content-Type: application/json' -d '{"erpRole":"purchase"}'` → `code:0` 且 `user.erpRole="purchase"`
- [ ] me：`curl -s http://localhost:3000/api/auth/me -H "Authorization: Bearer {token}"` → `code:0` 且含 `createdAt`
- [ ] logout：`curl -s -X POST http://localhost:3000/api/auth/logout -H "Authorization: Bearer {token}"` → `code:0`；随后同 token 调 me → 401

### 阶段 2：自测验收

- [ ] API 正向验证：4 端点各 ≥1 正向用例（200 结构 + 业务数据），operator 账号与 6 个角色账号逐一登录成功（AC-RULE-26）
- [ ] API 参数校验：login 缺 username/缺 password → 400 `"请输入账号和密码"`；role-login 缺 erpRole / `erpRole:"xxx"` → 400 `"erpRole 参数不合法"`
- [ ] API 业务规则验证：错误密码 → 401 统一文案 `"账号或密码错误"`（防枚举）；sales（role=user）走 login → 403 `"请使用选角色登录"`
- [ ] API 异常场景：me/logout 无 token → 401 `"未登录或登录已失效"`；伪造 token（`Bearer deadbeef`）→ 401
- [ ] 会话持久性（DB token）：登录 → 重启 server → 原 token 调 me 仍 200（重启不丢会话）
- [ ] 数据持久化：登录后 `auth_tokens` 表存在该 token 记录；logout 后记录删除（seed:check 或 node 查询断言）
- [ ] 自测报告含以上 curl 断言输出汇总（4 端点 × 正/异常）
