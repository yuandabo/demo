# FE-01 - m 端工程骨架与手机壳（m.html 入口 + PhoneShell 375 视口 + TabBar + 选角色登录半屏弹层）

<!-- REQUIRED:任务目标 -->
## 任务目标

**UI 设计稿路径**：`ui/ui_m_home.html`（手机壳/状态栏/TabBar/选角色弹层的统一样式定义，5 页原型共用同一套 CSS）

> 来源：[tech-design.md#2-现有代码基础与仓库结构](../../design/tech-design.md#2-现有代码基础与仓库结构) / [tech-design.md#7-前端架构第-8-章](../../design/tech-design.md#7-前端架构第-8-章)

搭建小程序 H5 端（m 端）工程骨架，被后续 5 个页面任务（FE-02~FE-06）复用：

1. 新增 Vite 第三入口 `web/m.html`（挂 `src/m/main.tsx`），vite.config.ts input 增加 m.html；
2. `src/m/App.tsx`：HashRouter + AuthProvider + 5 条路由（`#/`、`#/list`、`#/detail/:id`、`#/favorite`、`#/checkin`，本任务先挂占位页，页面任务逐个替换）；
3. **PhoneShell 组件**：375×812 手机壳（notch、statusbar、scroll 容器、homebar），375 视口自适应（AC-NF-03）；
4. **TabBar 组件**：首页/分类/收藏/打卡 4 tab，active 高亮随路由联动；
5. **RoleSheet 选角色登录半屏弹层**：6 个演示角色卡（销售/采购/生产/仓库/管理/财务），调 POST /api/auth/role-login；与 PC 前台共用同一套演示账号与登录态存储（AC-RULE-26），支持「登录后回到原页面原位置」（AC-FN-03 的 m 端承载组件，详情页/收藏页/打卡页触发）。

### 交互操作

> 每条操作必须包含以下全部描述项，缺一不可。
> 每条操作必须标注来源（PRD 章节 或 tech-design.md 章节），不允许无来源的内容。

**1. 应用初始化（登录态恢复）**
- 来源：[tech-design.md#7-前端架构第-8-章](../../design/tech-design.md#7-前端架构第-8-章)
- 触发：打开 m.html（任一路由首次加载）
- 前置条件：无
- 操作：GET /api/auth/me（携带 localStorage 中的 token）
- Loading 状态：statusbar 与页面正常渲染，弹层与请求不阻塞首屏
- 期望效果：token 有效 → AuthContext 写入用户（displayName、erpRole）；无效/无 token → 游客态，页面不报错
- 空态处理：游客态不显示角色名，触发互动接口时按 401 事件弹 RoleSheet

**2. 打开选角色登录弹层**
- 来源：[prd.md#711-公共账号-租户](../../prd/PRD.md#711-公共账号-租户) / [ac.md#AC-RULE-26](../../ac.md)
- 触发：点击头部角色徽章（页面任务提供触发点），或 401 登录事件（shared/api.ts 统一抛出）
- 前置条件：无（游客与已登录均可切换角色）
- 操作：无 HTTP 请求（纯 UI 展示）
- Loading 状态：无
- 期望效果：mask + sheet 展开（半屏弹层，6 角色卡可见）
- 空态处理：无

**3. 选角色快速登录**
- 来源：[ac.md#AC-FN-03](../../ac.md) / [get 路径 post-api-auth-role-login.md](../../design/api/post-api-auth-role-login.md)
- 触发：点击任一角色卡
- 前置条件：弹层已打开
- 操作：POST /api/auth/role-login `{"erpRole":"purchase"}`（枚举 sales/purchase/produce/warehouse/manage/finance）
- Loading 状态：角色卡按压反馈（:active），防止重复点击（选中即禁用其他卡）
- 期望效果：code=0 → token 与 user 写入 localStorage/AuthContext，关闭弹层，**回到原页面原位置**（记录弹层打开时的路由与滚动位置，登录后恢复并重放被拦截的操作）；code≠0 → 弹层内提示错误文案
- 空态处理：接口失败保留弹层与已选角色，提示重试

**4. TabBar 路由切换**
- 来源：[tech-design.md#7-前端架构第-8-章](../../design/tech-design.md#7-前端架构第-8-章)
- 触发：点击底部 tab
- 前置条件：无
- 操作：HashRouter 导航至 `#/`、`#/list`、`#/favorite`、`#/checkin`
- Loading 状态：无（客户端路由）
- 期望效果：active 高亮切换到目标 tab，对应页面渲染；detail 路由下无 tab 命中（详情页原型 active 在「分类」）
- 空态处理：无
