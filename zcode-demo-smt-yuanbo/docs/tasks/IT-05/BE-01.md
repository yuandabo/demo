# BE-01 - 消息接口 GET /api/messages（mock 消息按角色过滤）

<!-- REQUIRED:任务目标 -->
## 任务目标

> 来源：[tech-design.md#3-api-接口总览](../../design/tech-design.md#3-api-接口总览) / [tech-design.md#11-service-函数清单冻结命名评审修复补充](../../design/tech-design.md#11-service-函数清单冻结命名评审修复补充)

实现 GET /api/messages 接口：返回 messages 表中的 mock 审批待办消息（种子 3 条，均关联教程），支持按 erpRole 过滤；过滤优先级为「显式 erpRole 参数 > 登录用户角色 > 全部」。接口为公开接口（demo 演示场景，无登录态也可读取），实现于 `server/src/routes/misc.ts` 的 listMessages 函数，作为 m 首页「消息入口预留」卡片的唯一数据源（PRD §7.10 消息联动 v1.1 迭代池预留能力，本期仅数据与接口预留）。

**AC 关联说明**：本任务为纯数据预留类接口，ac.md 无消息专属 AC；分配 AC-FN-24 的原因——消息入口卡是 m 首页区块（AC-FN-24「小程序端首页」场景）的组成区块，该 AC 验收首页区块渲染时此卡片数据必须可取。

## 核心流程

> 每个步骤必须与 tech-design.md 中的业务逻辑一致，必须包含以下全部描述项，缺一不可。
> 每个步骤必须标注来源（tech-design.md 章节），不允许无来源的内容。

**1. 可选鉴权与角色解析**
- 来源：[tech-design.md#4-后端架构与处理流程](../../design/tech-design.md#4-后端架构与处理流程)
- 输入：请求头 `Authorization: Bearer {token}`（可选）
- 处理逻辑：无 token → 游客态直接放行（公开接口，不抛 401）；有 token → 查 auth_tokens JOIN users 解析 `erpRole`；token 无效时按游客态放行（demo 公开读取语义，取不到角色即不过滤）
- 校验规则（如有）：

  | 字段 | 规则 | 失败返回 |
  |------|------|---------|
  | Authorization | 可选；格式 `Bearer {token}` | 无效 token 不报错，降级为游客（不过滤角色） |

- 输出：`erpRoleOfUser: string | null`
- 异常处理：无（公开接口，无失败分支）

**2. 查询参数校验**
- 来源：[get-api-messages.md 业务规则与失败场景](../../design/api/get-api-messages.md)
- 输入：查询参数 `erpRole`（可选，String）
- 处理逻辑：`erpRole` 缺省 → 待过滤角色取登录用户角色；显式传入时必须 ∈ `['sales','purchase','produce','warehouse','manage','finance']`
- 校验规则：

  | 字段 | 规则 | 失败返回 |
  |------|------|---------|
  | erpRole | 可选；枚举 6 个 ERP 角色 | 400 `{code:400, message:"erpRole 参数不合法"}` |

- 输出：`filterRole: string | null`（null = 不过滤返回全部）
- 异常处理：非法枚举 → HTTP 400，code=400，message="erpRole 参数不合法"

**3. 消息查询（JOIN 教程标题）**
- 来源：[tech-design.md#4-后端架构与处理流程](../../design/tech-design.md#4-后端架构与处理流程)
- 输入：`filterRole`
- 处理逻辑：按角色过滤 messages 并按创建时间倒序；LEFT JOIN tutorials 取教程标题（tutorial_id 可为 null，预留场景）
- 数据库操作：

  | 操作 | SQL 骨架 | 说明 |
  |------|---------|------|
  | SELECT | `SELECT m.id, m.erp_role, m.title, m.tutorial_id, t.title AS tutorial_title, m.is_read, m.created_at FROM messages m LEFT JOIN tutorials t ON t.id = m.tutorial_id WHERE (? IS NULL OR m.erp_role = ?) ORDER BY m.created_at DESC` | prepared statement；`?` 传 filterRole（null 时全量） |

- 输出：消息行数组
- 异常处理：数据库异常 → 500 `{code:500, message:"系统异常"}`（统一错误中间件兜底）

**4. 组装响应**
- 来源：[get-api-messages.md 成功响应](../../design/api/get-api-messages.md)
- 输入：消息行数组
- 处理逻辑：映射为 `{id, erpRole, title, tutorialId, tutorialTitle, isRead, createdAt}` 数组；`tutorialId` 为 null 时 `tutorialTitle` 置 null
- 数据转换：`m.erp_role → erpRole`、`m.tutorial_id → tutorialId`、`m.is_read → isRead`、`m.created_at → createdAt`（蛇形转驼峰）
- 事务边界：只读查询，无事务
- 输出：`{code:0, message:"ok", data:{ list: [...] }}`
