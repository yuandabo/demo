# BE-04 - 教程审核状态机（提审/撤回/审核）

<!-- REQUIRED:任务目标 -->
## 任务目标

> 来源：[tech-design.md#4-后端架构与处理流程](../../design/tech-design.md#4-后端架构与处理流程) / [tech-design.md#11-service-函数清单冻结命名评审修复补充](../../design/tech-design.md#11-service-函数清单冻结命名评审修复补充)

实现教程四态状态机的审核闭环 3 端点，service 冻结命名：`submitTutorial / withdrawTutorial / reviewTutorial(id, {action, reason})`。

- POST /api/tutorials/:id/submit：草稿→待审核，submit_count+1；必填四项齐备才可提审（AC-EG-01）；仅草稿可提审，已下架直接提审属非法迁移 409（AC-EG-09）。
- POST /api/tutorials/:id/withdraw：待审核→草稿（AC-OP-07）；与审核动作并发互斥，后到失效 409（AC-EG-04）。
- POST /api/tutorials/:id/review：admin 专属（operator 403，AC-FN-18）；approve=唯一发布写入方，事务内拷贝快照（AC-FN-08）；reject 待审核→草稿，**驳回原因必填 ≥5 字，后端校验 400（AC-FN-09 / AC-RULE-19 双重校验的后端侧，必须实现）**；回审版驳回仅编辑版回草稿、前台旧版在线（AC-FN-19）。

<!-- REQUIRED:核心流程 -->
## 核心流程

**1. POST /:id/submit 提审**
- 来源：[../../design/api/post-api-tutorials-id-submit.md](../../design/api/post-api-tutorials-id-submit.md)
- 输入：path `id`；body 空
- 处理逻辑：鉴权 → 404 → 状态校验（转移表 submit：仅 draft，否则 409 "该教程状态已变化，请刷新"）→ 必填校验（title/categoryId/summary/content 均非空；categoryId 须启用分类，停用 409）→ 单语句 UPDATE：status='pending'、submit_count=submit_count+1
- 数据库操作：`UPDATE tutorials SET status='pending', submit_count=submit_count+1 WHERE id=? AND status='draft'`（WHERE 条件兜底并发，影响行数=0 时再读状态返回 409）
- 输出：`{code:0, data:{id, status:'pending', submitCount}}`（submitCount 驱动审核队列 v2+ 标识）
- 异常处理：必填缺失 400 "请补全标题/分类/摘要/正文后再提交"；长度越界 400；停用分类 409；非法迁移 409；401/403/404

**2. POST /:id/withdraw 撤回**
- 来源：[../../design/api/post-api-tutorials-id-withdraw.md](../../design/api/post-api-tutorials-id-withdraw.md)
- 处理逻辑：鉴权 → 404 → 转移表 withdraw（仅 pending，否则 409）→ UPDATE status='draft'；撤回后前台旧版（若有）继续在线由快照列保证，无需额外处理
- 数据库操作：`UPDATE tutorials SET status='draft' WHERE id=? AND status='pending'`
- 输出：`{code:0, data:{id, status:'draft'}}`
- 异常处理：非待审核（含与管理员审核并发后到失效）→ 409 "该教程状态已变化，请刷新"（AC-EG-04）

**3. POST /:id/review 审核（approve / reject）**
- 来源：[../../design/api/post-api-tutorials-id-review.md](../../design/api/post-api-tutorials-id-review.md)
- 输入：path `id`；body `{ action: 'approve'|'reject', reason? }`
- 校验规则：

| 字段 | 规则 | 失败返回 |
|------|------|---------|
| action | required，枚举 approve/reject | 400 "action 参数不合法" |
| reason | action=reject 时必填且 trim 后 ≥5 字（后端二次校验） | 400 "请填写至少 5 个字的驳回原因" |

- 处理逻辑（approve，事务）：
  1. admin 鉴权 → 404 → 转移表 reviewApprove（仅 pending，否则 409）
  2. 事务：`UPDATE status='published', reviewer_id=当前admin, reviewed_at=now` + `UPDATE SET published_content=content, published_summary=summary, published_at=now, last_offline_at=NULL, updated_at=now` + reject_reason 置 NULL
  3. 快照拷贝是唯一 approve 写入方：前台列表/详情下一次请求即返回新版（无需重启，AC-FN-08）
- 处理逻辑（reject）：转移表 reviewReject（仅 pending）→ `UPDATE status='draft', reject_reason=reason, reviewer_id, reviewed_at=now, updated_at=now`；快照列不动——回审版驳回仅编辑版回草稿，前台继续展示线上过审版本（AC-FN-19）
- 输出：approve `{id, status:'published', publishedAt, reviewerId, reviewedAt}`；reject `{id, status:'draft', rejectReason}`
- 异常处理：operator/user 403 "无权限执行该操作"（教程状态不变，AC-FN-18）；**驳回原因 <5 字 400 "请填写至少 5 个字的驳回原因"（必须实现）**；action 非法 400；非待审核 409；404/401

## 验收标准

### 阶段 1：开发验收

- [ ] `getDiagnostics` 0 Error；构建通过
- [ ] curl 提审：`curl -X POST http://localhost:3000/api/tutorials/25/submit -H 'Content-Type: application/json' -H 'Authorization: Bearer {operatorToken}' -d '{}'` → 200，status=pending，submitCount 递增
- [ ] curl 审核通过：`curl -X POST http://localhost:3000/api/tutorials/25/review -H 'Content-Type: application/json' -H 'Authorization: Bearer {adminToken}' -d '{"action":"approve"}'` → 200，含 publishedAt/reviewerId/reviewedAt
- [ ] curl 异常：operator 调 review → 403 "无权限执行该操作"；action 缺失 → 400 "action 参数不合法"

### 阶段 2：自测验收

- [ ] **驳回原因 ≥5 字双重校验（显式验收）**：`{"action":"reject","reason":"太短"}` → 400 "请填写至少 5 个字的驳回原因"；补足 5 字 → 200，教程回草稿且管理列表 rejectReason 非空（AC-FN-09 / AC-RULE-19）
- [ ] **非法迁移 409（显式验收）**：草稿直接 review（绕过提审）→ 409 "该教程状态已变化，请刷新"；已下架教程直接 submit → 409 且状态保持 offline（AC-EG-09 / AC-RULE-05）
- [ ] approve 后快照验证：GET /api/tutorials/:id 返回新 content；published_content=published_summary=published_at 落库；last_offline_at=NULL；前台列表下一次请求即包含（AC-FN-08）
- [ ] 回审版驳回（AC-FN-19）：已发布教程 PUT 保存（回审）→ review reject → status=draft、前台仍返回旧版快照内容
- [ ] 提审必填（AC-EG-01）：缺摘要/正文/标题/分类任一 → 400 "请补全标题/分类/摘要/正文后再提交"
- [ ] 并发互斥（AC-EG-04）：先 withdraw 再 review 同一篇 → review 收到 409；先 review 再 withdraw → withdraw 收到 409
- [ ] 撤回（AC-OP-07）：pending withdraw → draft，管理列表状态变更，可再次 submit
- [ ] 提审留痕：submit_count 累计递增（v2 标识数据源）；review 后 reviewer_id/reviewed_at 非空（AC-NF-04 留痕）
- [ ] 持久化验证：审核事务原子性——approve 后 status/快照列/计数一次查询全部就位
