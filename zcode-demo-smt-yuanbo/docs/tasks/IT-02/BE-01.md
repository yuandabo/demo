# BE-01 - 分类管理接口（树/增/改/删，含 409 删除保护）

<!-- REQUIRED:任务目标 -->
## 任务目标

> 来源：[tech-design.md#11-service-函数清单冻结命名评审修复补充](../../design/tech-design.md#11-service-函数清单冻结命名评审修复补充) / [tech-design.md#3-api-接口总览](../../design/tech-design.md#3-api-接口总览)

实现 routes/categories.ts 全部 4 个端点，service 冻结命名：`getCategoryTree / createCategory / updateCategory / deleteCategory`。

- GET /api/categories：两级树；前台口径仅启用分类，`all=1`（admin）返回含停用全量；`withCount=1` 附带 tutorialCount（前台可见口径角标，复用 INFRA-01 的 VISIBLE_SQL）。
- POST /api/categories：admin 专属新增（初始 enabled），本期限两级（parentId 只能是一级）。
- PUT /api/categories/:id：名称/父分类/排序/启停/模块映射共用（AC-OP-04 模块映射维护、AC-RULE-07 停用语义）。
- DELETE /api/categories/:id：admin 专属；**删除保护：分类（含子分类）下存在任意状态教程时 409 "该分类下还有 N 篇教程，请先移走"（AC-FN-13，必须实现）**；存在子分类 409 "该分类下存在子分类，请先处理"。

## 核心流程

**1. GET /api/categories 分类树**
- 来源：[../../design/api/get-api-categories.md](../../design/api/get-api-categories.md)
- 输入：query `withCount`（0/1）、`all`（0/1）
- 处理逻辑：读 categories 全表 → 内存组装两级树（parentId=null 为一级，sort 升序）→ 非 all 时过滤 status='enabled' → withCount=1 时逐分类按 VISIBLE_SQL 统计 tutorialCount（一级含子分类汇总、二级为直接计数）
- 数据库操作：

| 操作 | SQL 骨架 | 说明 |
|------|---------|------|
| SELECT | `SELECT * FROM categories ORDER BY sort ASC` | 树数据源 |
| SELECT | `SELECT t.category_id, COUNT(*) FROM tutorials t WHERE {VISIBLE_SQL} GROUP BY t.category_id` | 角标计数（前台可见口径） |

- 输出：`{code:0, data:{list:[{id,name,parentId,sort,status,erpModule,tutorialCount?,children:[]}]}}`
- 异常处理：all=1 未登录 → 401 "未登录或登录已失效"；all=1 非 admin → 403 "无权限执行该操作"

**2. POST /api/categories 新增**
- 来源：[../../design/api/post-api-categories.md](../../design/api/post-api-categories.md)
- 输入：body `{ name, parentId?, sort?, erpModule?, status? }`
- 校验规则：

| 字段 | 规则 | 失败返回 |
|------|------|---------|
| name | required，trim 非空，长度 1-50 | 400 "分类名称不能为空且不超过 50 字" |
| parentId | 可空；须存在且为一级（parent_id IS NULL） | 404 "父分类不存在" / 400 "本期限两级分类，父分类必须为一级分类" |
| erpModule | 八枚举或 null | 400 "erpModule 参数不合法" |
| sort | 0-9999 整数，默认 0 | 400 "查询参数不合法" |

- 处理逻辑：权限校验（admin）→ 参数校验 → 插入（status 默认 enabled，updated_at=now）
- 数据库操作：`INSERT INTO categories(name,parent_id,sort,status,erp_module) VALUES(?,?,?,?,?)`（prepared）
- 输出：`{code:0, data:{id, name, parentId, sort, status, erpModule, createdAt}}`
- 异常处理：未登录 401；operator/user 403 "无权限执行该操作"

**3. PUT /api/categories/:id 编辑（含模块映射/启停/排序）**
- 来源：[../../design/api/put-api-categories-id.md](../../design/api/put-api-categories-id.md)
- 输入：path `id`；body 任选 `{ name?, parentId?, sort?, status?, erpModule? }`（不传不改）
- 处理逻辑：admin 校验 → 404 存在性 → 字段校验（name 长度 1-50 / erpModule 八枚举或 null / sort 0-9999 / status 枚举 enabled|disabled）→ 防环校验（parentId 不得指向自身或其子孙）→ 更新并刷新 updated_at；erpModule 传 null 解除映射（AC-OP-04）；status 切换承载 AC-RULE-06/07 启停语义（前台可见性由 GET 端过滤与 tutorials 检索侧共同生效）
- 数据库操作：`UPDATE categories SET ... , updated_at=datetime('now','localtime') WHERE id=?`
- 输出：`{code:0, data:{id,name,parentId,sort,status,erpModule,updatedAt}}`
- 异常处理：防环/限两级 400；分类不存在 404 "分类不存在"；非 admin 403

**4. DELETE /api/categories/:id 删除（删除保护）**
- 来源：[../../design/api/delete-api-categories-id.md](../../design/api/delete-api-categories-id.md)
- 输入：path `id`
- 处理逻辑：admin 校验 → 404 存在性 → **删除保护判定**：统计该分类及其子分类下任意状态教程数 N（含草稿/待审核/已发布/已下架）→ N≥1 时 409；存在子分类时 409；通过后物理删除
- 数据库操作：

| 操作 | SQL 骨架 | 说明 |
|------|---------|------|
| SELECT | `SELECT COUNT(*) AS n FROM tutorials WHERE category_id IN (子分类id集 ∪ {id})` | 任意状态教程计数（删除保护） |
| DELETE | `DELETE FROM categories WHERE id=?` | 仅空分类放行 |

- 输出：`{code:0, message:"已删除", data:null}`
- 异常处理：**409 "该分类下还有 N 篇教程，请先移走"（AC-FN-13 字面文案，必须实现）**；409 "该分类下存在子分类，请先处理"；404 "分类不存在"；401/403

## 验收标准

### 阶段 1：开发验收

- [ ] `getDiagnostics` 0 Error；构建通过
- [ ] curl 正常返回 200：`curl 'http://localhost:3000/api/categories?withCount=1'` → 12 个启用一级分类树 + tutorialCount
- [ ] curl 管理态：`curl -X POST http://localhost:3000/api/categories -H 'Content-Type: application/json' -H 'Authorization: Bearer {adminToken}' -d '{"name":"报表中心","parentId":null,"sort":13}'` → code 0，status=enabled
- [ ] curl 异常场景：operator token 调 POST → 403 "无权限执行该操作"；未登录 all=1 → 401
- [ ] curl 模块映射：`curl -X PUT http://localhost:3000/api/categories/2 -H 'Authorization: Bearer {adminToken}' -d '{"erpModule":"purchase"}'` → updatedAt 刷新

### 阶段 2：自测验收

- [ ] **删除保护（显式验收）**：对种子"销售管理"（下有 3 篇教程）执行 DELETE → 409 且 message="该分类下还有 3 篇教程，请先移走"，分类树中该分类仍存在（AC-FN-13）
- [ ] 对自建的 0 教程无子分类空分类执行 DELETE → 200 "已删除"，树中移除
- [ ] 有子分类的一级分类 DELETE → 409 "该分类下存在子分类，请先处理"
- [ ] name 超 50 字 / 空白 → 400；parentId 指向二级 → 400；parentId 指向不存在 → 404；erpModule 非枚举 → 400
- [ ] PUT 防环：把一级分类 A 的 parentId 指向其子分类 → 400 "不允许将分类移动到自身或其子分类下"
- [ ] withCount=1 时停用分类下已发布教程不计入任何启用分类角标外的可见计数；all=1 可见停用分类、无 all 时被过滤（AC-RULE-06/07）
- [ ] 持久化验证：新增/修改后重启服务数据仍在（erp.db 落盘）
